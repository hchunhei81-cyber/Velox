01 / OVERVIEW

认识 Velox

Velox 是一门正在自举（self-hosting）过程中的编程语言。当前工程采用 Rust 编写 Stage 0 编译器，再由 Velox 编写 Stage 1 编译器，并通过 C 代码生成与本机 C 编译器构建后续阶段。

01

Readable

采用显式函数、类型注解、代码块和直观的控制流程。

02

Typed

具有 i64、f64、bool、str、void 与结构体类型等基础类型。

03

Native

当前后端将 Velox 程序转换为 C，再调用 clang 等 C 编译器生成本机可执行文件。

02 / QUICK START

快速开始

在仓库根目录执行以下命令。由于工程包含多个 Cargo binary，调用编译器时请明确指定 --bin veloxc。

环境要求

  • Rust 工具链与 Cargo：构建 Stage 0 编译器。
  • C 编译器（例如 clang）：将生成的 C 源码编译为本机程序。
  • 终端：在仓库根目录运行命令。
TERMINAL · BUILD COMPILER
cargo build --release --bin veloxc
HELLO.VX
fn main() {
    println("Hello, Velox!");
}
COMPILE · RUN
cargo run --release --bin veloxc -- hello.vx -o hello
./hello

提示：上面的调用方式与当前项目测试/开发流程一致。若你使用已构建的 veloxc，可直接调用 target/release/veloxc，并保留相同的源文件与 -o 参数形式。

03 / SOURCE FORMAT

文件格式与代码风格

源文件

Velox 源代码使用 .vx 扩展名。文件通常以 using 声明依赖，再定义结构体、函数和 main 入口。

  • 语句以分号结束。
  • 代码块使用花括号。
  • 类型注解写在变量名之后。

变量声明

let 声明局部变量；let mut 声明可变变量。类型可以显式写出。当前编译器支持的类型推断仍在完善中，建议初学时优先写出类型注解。

VARIABLES

let price: f64 = 3.5;
let ready: bool = true;
let title: str = "Velox";

let mut total: i64 = 0;
total = total + count;
let 与 let mut

不可变绑定用于不会重新赋值的变量；需要重新赋值时使用 let mut。不要将 mut 放在类型前面。

06 / CONTROL FLOW

流程控制

if / else

CONDITIONAL
fn classify(value: i64) -> i64 {
    if value > 0 {
        return 1;
    } else {
        return 0;
    }
}

while

WHILE LOOP
fn main() -> void {
    let mut index: i64 = 0;
    while index < 3 {
        println(index);
        index = index + 1;
    }
}

for / range

RANGE LOOP
fn main() -> void {
    for index in 0..5 {
        println(index);
    }
}

范围循环示例使用 0..5。当前项目测试已覆盖类似 0..3 的循环形式；范围边界的精确语义请以当前 parser/codegen 测试为准。

07 / FUNCTIONS

函数

使用 fn 声明函数。参数采用 name: type 形式；返回类型通过 -> 指定。没有返回值的函数可使用 void。

FUNCTION DECLARATION
fn add(a: i64, b: i64) -> i64 {
    return a + b;
}

fn main() -> void {
    let answer: i64 = add(20, 22);
    println(answer);
}
  • 函数名后面紧跟参数列表。
  • 参数之间使用逗号分隔。
  • return 用于从函数返回值。
  • main 是当前示例和编译入口使用的程序入口函数。
08 / STRUCTS

结构体

使用 struct 定义聚合数据类型。字段声明由字段名和类型组成；初始化时使用结构体名与命名字段。

STRUCT DEFINITION & INITIALIZATION
struct Point {
    x: f64,
    y: f64
}

fn main() -> void {
    let point: Point = Point {
        x: 3.0,
        y: 4.0
    };
    println(point.x);
}

注意：结构体定义、初始化与字段访问已进入项目实现范围；局部变量自动推断、结构体返回值推断等代码生成边界仍应通过回归测试确认。教程示例显式标注 Point 类型。

09 / MODULES

模块与依赖

当前项目使用 using "path.vx"; 引入其他源文件。依赖路径按引用文件位置解析；编译器会收集依赖并在依赖方之前处理。

IMPORT A SOURCE FILE
// main.vx
using "math.vx";

fn main() -> void {
    println(add(20, 22));
}
DEPENDENCY FILE
// math.vx
fn add(a: i64, b: i64) -> i64 {
    return a + b;
}
依赖检查

编译器会避免重复处理同一依赖，并检测循环依赖。当前回归测试中，循环依赖会报告 E0203。

13 / SELF-HOSTING

Stage 0 → Stage 1 → Stage 2 → Stage 3

Velox 的关键里程碑是用 Velox 编译器编译 Velox 编译器自身。当前仓库的 Stage 0 是 Rust 编译器；Stage 1 是由 Stage 0 编译出来的 VX 编译器；Stage 1 生成 Stage 2，后续阶段继续编译同一份 VX 编译器源码。

STAGE 0

Rust 实现的引导编译器。

STAGE 1

由 Stage 0 编译 selfhost/src/main.vx 得到的 VX 编译器。

STAGE 2

由 Stage 1 执行并生成的下一阶段编译器。

STAGE 3+

继续自编译，并检查生成结果是否稳定。

确定性验证

项目已验证 Stage 2 与 Stage 3 生成的 C 文件逐字节一致，并且 Stage 3 能再次执行自编译流程。这是重要的自举一致性证据，但不等同于所有语言功能均已完成。

14 / TROUBLESHOOTING

常见错误与排查

Cargo 提示有多个 binary

命令中指定编译器目标：cargo run --bin veloxc -- ...。不要省略 --bin veloxc。

找不到 clang

安装并配置可用的 C 编译器，确认 clang 在 PATH 中；Velox 当前后端依赖外部 C 编译器生成本机程序。

结构体局部变量编译失败

开发阶段优先显式标注变量类型，例如 let p: Pair = Pair { ... };。自动推断路径仍需由 codegen 回归测试确认。

循环依赖

检查 using 文件关系是否形成环。当前驱动器的循环依赖回归使用错误码 E0203。

程序输出与预期不同

先确认 parser 和 type checker 均通过，再检查生成的 C 文件；最后单独编译并运行 C 输出，以区分前端、后端与本机编译阶段的问题。

15 / COMPLETE EXAMPLE

完整示例：从定义到运行

MAIN.VX
struct Pair {
    left: i64,
    right: i64
}

fn add(a: i64, b: i64) -> i64 {
    return a + b;
}

fn main() -> void {
    let pair: Pair = Pair {
        left: 20,
        right: 22
    };

    let answer: i64 = add(pair.left, pair.right);
    println(answer);
}
